# Lab Atlas「论文信息处理流程」页面文案源稿

这份文档是 `workflow.html` 的文字底稿。它同时服务于两种阅读方式：读者先看图，了解信息怎样从实验室主页逐步变成论文、作者和引用特征；读者再看图下的段落，了解每一步为什么存在、输入是什么、输出怎样交给下一步。文案保持长期有效，不写运行进度、数据统计、队列数量、快照日期或版本发布消息。

## 一、页面定位

### 页面标题

**论文信息处理流程**

### 页面顶栏标签（`.design-label`）

**实验室资料 · OpenAlex**

### 页面副标题

**从实验室主页清单到可追溯的论文、作者与引用特征**

### 页面开头的引导段

Lab Atlas 的论文地图从实验室主页开始。主页适合日常阅读，但其中的标题、署名、年份、发表情况和链接仍然是展示文本；论文地图还需要知道每篇记录对应数据库中的哪一部具体作品、有哪些可靠的作者实体、它主动引用了哪些文献、哪些文献引用了它，以及哪些内容可以用于语义相似度和作者画像计算。

流程图横向展示这些信息的处理顺序。每一列代表一个处理阶段，每一行代表一类数据泳道，每个方框代表一项数据，圆角矩形代表一个处理动作，从左向右的箭头表示数据交接。浅色白底方框（未定稿信息）表示进入当前阶段前已经存在的原始或待补全输入，带底色的彩色方框（已定稿信息）表示该阶段形成或确认的结果。读者可以悬浮或点击阶段表头、左侧行标签、处理动作、数据节点和连线，查看对应的局部说明。

### 右上角「数据说明」弹窗文案（`#info`）

* **弹窗标题**：数据来源与覆盖范围


* **第一段**：基础论文事实、人员归属与引用关系来自实验室主页原始 HTML 快照、用户确认的实验室人员名单和 OpenAlex 数据库。主页原始字段持续保留；Semantic Scholar、Crossref、Google Scholar、DBLP 和独立论文发布页不属于标准采集来源。


* **第二段**：论文关键词由标题和可用摘要在版本化的受控关键词词表内标注，每项均附带连续原文证据；研究领域用于筛选和染色；内容相似度使用固定版本的本地 SPECTER2 语义向量。


* **第三段**：外部文献来自实验室论文的一层引用与被引邻域。完整外部记录保留在数据层，网络节点仅纳入与至少两篇不同实验室论文存在直接引用或被引关系的外部作品，外部文献之间不绘制引用边。

## 二、读者需要先知道的术语

| 术语 | 页面中的定义 |
| --- | --- |
| 实验室主页清单 | 实验室网站上列出的论文条目，通常包含标题、作者、年份、会议或期刊、预印本状态和链接。

 |
| 论文记录 | 系统内部代表一篇实验室论文的去重结构化记录。它保留主页原文，并保存后续身份核对与详情采集结果。

 |
| occurrence（展示记录） | 一条论文在主页上的一次具体展示记录。同一论文出现在主页不同栏目或年份列表时，每次展示的原始文本、所在栏目和顺序仍分别保留。

 |
| 论文身份 | OpenAlex work ID、最终采用标题、作者顺序、DOI、发表年份、发表载体、论文类型、正式版或预印本状态及版本判断依据共同描述的作品对应关系。

 |
| OpenAlex work ID | OpenAlex 为一部论文作品分配的稳定标识，是精确详情和双向引用查询的唯一入口。

 |
| OpenAlex author ID | OpenAlex 为一名数据库作者分配的标识。它描述数据库中的作者身份，仍需与逐篇署名和实验室人员实体分别保存。

 |
| DOI / arXiv 标识 | 论文常见的外部标识符，用于优先建立 OpenAlex 候选并在匹配规则中提供直接指向依据。

 |
| 论文详情 | 确认 OpenAlex work ID 后重新执行精确查询取得的摘要、数据库关键词、数据库主题、被引统计和双向引用关系等论文自身信息。

 |
| 引用文献 | 论文主动引用的其他作品（`referenced_works`）。

 |
| 被引记录 | 引用该论文的其他作品（通过被引查询接口获取）。

 |
| 外部文献 | 不在实验室论文集合中、但出现在实验室论文一层引用或被引关系中的作品。

 |
| 一层邻域 | 只沿实验室论文的引用文献和被引记录向外扩展一步得到的外部文献集合；外部文献继续引用的作品不再递归展开。

 |
| 语义向量 | 使用固定版本的本地 SPECTER2 模型对论文标题和合格摘要生成的定长 L2 归一化数字表示，用于计算论文或作者之间的内容关联。

 |
| 受控关键词 | 来自版本化受控关键词词表的关键词标签。每个标签都必须在该论文标题或摘要中找到连续原文引文证据。

 |
| 作者 occurrence | 某篇论文中的一次具体作者署名，包含论文 ID、作者顺序、姓名、OpenAlex author ID、ORCID、机构和逐篇作者键。

 |
| 作者画像 | 把已经归一到同一实验室人员的论文受控关键词和语义特征，按署名位置权重聚合归一化得到的结果。

 |

## 四、五个阶段的页面文案

以下内容用于阶段标题卡片、阶段说明、阶段悬浮框和图下的详细段落。阶段卡片使用“短说明”；悬浮框使用“输入 / 动作 / 输出 / 状态”；图下段落使用“详细说明”。

### 阶段一：整理实验室清单

**短说明**

解析实验室主页原始 HTML，保留每次论文展示的原文与位置，并去重生成唯一论文记录。

**输入**

* 实验室主页原始 HTML 快照。


* 主页地址和原始文件指纹。


* 用户确认的实验室人员名单。



**主要动作**

解析主页中的论文段落，提取原始标题、原始作者字符串、年份、会议或期刊发表情况、DOI 或 arXiv 等外部链接、所在栏目和原始顺序。对标题执行 Unicode NFKC、大小写归一、连字符与空白归一、去除不可见字符以及明显排版差异处理，仅用于识别重复展示和构造后续查询文本；主页原始文本、栏目位置和顺序原样保留。

同一篇论文在主页不同栏目或年份中重复出现时，保留每一次展示的 occurrence 记录，同时合并生成一个去重后的唯一论文 ID。这一阶段只整理主页自身信息，不访问 OpenAlex，也不使用数据库字段覆盖主页原文。

**输出**

* `01-homepage.json` 与主页原始文件指纹。


* 论文展示记录（occurrence）列表。


* 去重后的唯一论文列表（含主页标题、署名、发表情况与链接）。


* 解析失败和排除项列表。



**交接给下一阶段**

去重后的唯一论文列表、主页内含的标识符以及用户确认的实验室人员名单交给“核对论文与作者身份”。主页原始标题、署名和发表情况同时作为候选检索线索与后续比对基准。

**可能产生的状态**

已确认（`ready`）、字段缺失（`missing`）、内容无效（`invalid`）。

**阶段悬浮说明**

> 这一阶段回答“实验室主页列出了什么”。它完整保留主页原始段落、栏目和顺序，通过排版规范化识别重复展示并建立唯一论文 ID。本阶段不访问外部数据库，主页上的每次展示均可原样回溯。
> 
> 

### 阶段二：核对论文与作者身份

**短说明**

按固定路径检索 OpenAlex 身份字段，联合核对标题、署名、年份、载体与版本关系，确认唯一作品标识并提取逐篇作者署名。

**输入**

* 阶段一去重后的主页论文记录（原始标题、署名、年份、发表情况、DOI / arXiv 标识）。


* OpenAlex 搜索接口返回的候选记录。


* 用户确认的实验室人员名单。



**主要动作**

对每篇主页论文按以下顺序建立候选：1. 主页 DOI 查询；2. 主页 arXiv 标识查询；3. OpenAlex `search.title` 完整标题查询；4. OpenAlex `search` 完整标题查询；5. 对未确定条目执行有限标题变体查询（固定拼写修正、连字符与空格变体、冒号前后片段、长标题前后半段）。每条查询均保存查询类型、查询字符串、请求地址、HTTP 状态、返回时间、响应指纹、候选数量和筛选结果。身份搜索阶段只保留 OpenAlex ID、标题、DOI、其他 IDs、论文类型、发表年份、作者列表、主要与次要发表位置等纯身份字段，搜索附带的摘要、被引数、引用列表、主题和关键词不进入采用结果。

候选判断联合检验五个维度：标题允许 Unicode 排版、大小写、标点、空白、连字符、连字字符及固定记录拼写错误的自动归一，但增加、删除或替换研究任务、方法或对象词汇的实质性标题变化需要额外证据；年份允许有限差异并记入指标，但不能单独覆盖其他冲突；作者需满足固定交集数量、固定交集比例、主页 DOI/arXiv 直接指向，或在 OpenAlex 缺少作者名单时满足标题、年份、发表载体和正式版本条件全部严格吻合（主页作者名单与数据库作者名单分别保存，数据库缺失作者时不覆盖主页作者）；发表载体将常见会议简称与完整名称统一到规范名称后匹配，同时保留原始名称；数据集、项目页面、资助记录、参考文献条目、版式或附属记录等非论文对象直接排除。同一作品存在预印本与正式版时，需同时满足同一标题家族、作者顺序完整兼容、年份与载体符合版本关系且属于可接受正式论文类型，才优先采用正式版；同标题但作者顺序不兼容的候选不自动合并。

每篇主页论文最终得到唯一确认、正式版优先确认、未匹配、多个候选无法区分或查询失败五种身份决策之一。身份确认后，系统提取每篇论文的作者 occurrence（姓名、顺序、OpenAlex author ID、ORCID、机构、论文 ID、原始姓名及主页人员名单候选）；姓名规范化只处理大小写、标点、`Lastname, Firstname` 形式、OpenAlex 导出的 `id_orcid` 尾部和明确排版差异。论文身份核对与实验室人员归一是两个独立动作，姓名相同不能单独产生跨论文人员合并。

**输出**

* 采用的论文标题、作者名字及顺序、论文录用情况。


* 确认的 OpenAlex work ID、版本状态与判断依据。


* 候选列表、查询路径、候选评分与决策指纹。


* 逐篇作者署名记录（occurrence）列表。


* 未确认论文的主页保留记录与未确定状态。



**交接给下一阶段**

确认的 OpenAlex work ID 与身份签名交给“采集论文详情”；逐篇作者 occurrence 交给阶段五的人员归一流程；未确认论文保留主页记录与全部查询路径，详情字段保持身份未确定状态（`identity_unresolved`）。

**可能产生的状态**

已确认（`ready`）、身份未确定（`identity_unresolved`）、多候选歧义（`ambiguous`）、查询失败（`query_failed`）、字段缺失（`missing`）。

**阶段悬浮说明**

> 这一阶段回答“主页条目对应 OpenAlex 中哪一部具体作品”。系统按 DOI、arXiv、标题限定和标题变体顺序检索纯身份字段，联合校验标题词汇、作者交集、年份、载体与正式版兼容性。只有唯一确认的 work ID 才会进入详情采集。
> 
> 

**AI 边界悬浮说明**

> 论文身份 AI 审查属于独立的可选步骤，只读取已保存的主页记录、OpenAlex 候选、查询路径和规则指标，输出 `agree`、`needs_rule_revision` 或 `insufficient_evidence` 建议。AI 不查询外部网站、不创建 ID、不用语义相似标题替代身份，也不直接修改采用结果。
> 
> 

### 阶段三：采集论文详情

**短说明**

对阶段二确认的 OpenAlex work ID 重新执行精确查询，采集论文内容、统计指标和双向引用名单。

**输入**

* 阶段二确认的 OpenAlex work ID。


* 阶段二锁定的论文身份签名（ID、规范化标题、DOI、有序作者、年份、发表载体、正式版状态）。



**主要动作**

对每个确认的 work ID 重新发起精确详情查询与被引记录查询，不使用身份搜索阶段缓存的额外字段。采集摘要、OpenAlex `keywords`、OpenAlex `topics`、`cited_by_count`、`counts_by_year`、`referenced_works`、被引记录查询结果以及 DOI、发表日期、期刊或会议、作者和版本信息。

摘要通过固定质量规则检查：验证是否确为自然语言摘要文本，排除会议元信息、网页提示语、访问错误页面或重复字段；无效摘要保留原始响应和原因，标记为 `invalid`，不进入语义向量或关键词任务。被引次数同时保存 OpenAlex 主记录的 `cited_by_count`、被引查询接口返回的总数、查询时间、查询参数和查询完整性状态；采用规则优先使用被引查询报告总数，保留主记录计数作为对照，且不用被引名单长度替代被引次数。引用文献（主动引用的作品）与被引记录（引用该论文的作品）使用不同字段和查询路径分别保存，独立记录空列表、查询失败、分页未完成和身份未确定状态。

精确详情查询同步执行身份漂移检查：若返回结果的标题、DOI、有序作者、年份、载体或正式版签名发生变化，阶段二身份保持不变，阶段三详情不覆盖阶段二身份，变化记录进入身份漂移队列，需重新经过身份规则检验后才能采用新版本。

**输出**

* 经过质量检查的摘要。


* 数据库关键词（OpenAlex `keywords`）与数据库主题（OpenAlex `topics`）。


* 被引数（含多观察值对照）与年度被引数。


* 引用文献 ID 列表与被引记录 ID 列表。


* 字段状态、分页状态与身份漂移检查记录。



**交接给下一阶段**

确认的实验室论文标题与合格摘要交给“生成文献特征”；实验室论文 ID 集合、引用文献 ID 列表和被引记录 ID 列表交给“补全外部文献”。

**可能产生的状态**

已确认（`ready`）、明确为空（`empty`）、字段缺失（`missing`）、结果部分取得（`partial`）、内容无效（`invalid`）、查询失败（`query_failed`）、身份未确定（`identity_unresolved`）。

**阶段悬浮说明**

> 这一阶段只对确认的 OpenAlex work ID 重新执行精确查询。摘要需通过自然语言质量校验，主记录被引数、查询接口总数与被引名单长度分别保存；若检测到身份签名变化，记录退回身份核对阶段处理。
> 
> 

### 阶段四：补全外部文献

**短说明**

沿实验室论文的一层引用和被引名单查询外部作品详情，合并重定向记录并筛选双连接核心网络节点。

**输入**

* 阶段三确认的实验室论文 ID 集合。


* 实验室论文的引用文献 ID 列表。


* 实验室论文的被引记录 ID 列表。



**主要动作**

收集实验室论文主动引用的作品与引用实验室论文的作品，去除实验室论文自身后，对所有唯一外部 ID 查询详情。查询采用“先批量查询、批量遗漏 ID 再逐个精确查询”的策略，完整记录 HTTP 404、查询失败和 OpenAlex canonical redirect，使用 canonical ID 合并重复记录；若某条外部记录后来被识别为实验室论文，则重新划入实验室集合。查询范围严格只扩展一层外部邻域，不递归查询外部论文继续引用的作品，也不建立外部文献之间的引用边。

完整外部记录与网络节点集合分开保存。网络候选节点必须满足硬性条件：该外部文献与至少两篇不同实验室论文存在直接引用或被引关系。连接数计算依据完整的引用和被引名单，按 canonical OpenAlex ID 去重，同一对论文的重复关系只算一次，相反方向的关系对同一邻居只算一个；该计算在语义边、页面筛选和其他 UI 规则之前完成，不叠加年份或被引次数门槛，也不用单连接文献补满预算（存在预算上限时，按连接到不同实验室论文的数量降序排序，再以 OpenAlex ID 作为稳定并列排序键）。

**输出**

* 外部文献信息（每个外部 ID 的请求 ID、canonical ID、查询状态、标题、作者、年份、载体、摘要、被引数、topics、keywords、关联实验室论文、关系方向及失败原因）。


* 引用文献（补全后）与被引记录（补全后）。


* 满足至少连接两篇不同实验室论文门槛的网络节点集合。



**交接给下一阶段**

符合网络筛选条件的外部论文标题与合格摘要（连同实验室论文标题与摘要）交给阶段五生成文献特征；补全后的双向引用关系与网络节点集合提供给可视化网络与检索汇总页面。

**可能产生的状态**

已确认（`ready`）、明确为空（`empty`）、字段缺失（`missing`）、结果部分取得（`partial`）、查询失败（`query_failed`）。

**阶段悬浮说明**

> 这一阶段将视野扩展到实验室论文的一层引用与被引邻域。系统通过批量结合单篇补查取得外部文献详情并处理 canonical ID 重定向；完整外部记录全部保留，而进入图谱网络的外部节点必须至少直接连接两篇不同的实验室论文。
> 
> 

### 阶段五：生成文献特征与作者画像

**短说明**

基于锁定的论文文本、版本化的受控关键词词表和人员证据链，生成 SPECTER2 语义向量、受控关键词、研究领域标签及加权作者画像。

**输入**

* 实验室论文及入选网络外部论文的锁定标题与合格摘要（无摘要时仅用标题，保存精确输入指纹）。


* 固定版本的本地 SPECTER2 模型配置与权重。


* 版本化的受控关键词词表（含关键词 ID、中英文名称、定义、同义词、所属维度、父级词、使用边界）与固定 prompt。


* 满足严格输入一致性条件的旧关键词标注。


* 阶段二提取的逐篇作者 occurrence、OpenAlex 作者信息、用户实验室人员名单及固定同名分离约束。



**主要动作**

* **文献向量生成**：将标题与合格摘要拼接（摘要缺失时仅用标题），输入固定版本的本地 SPECTER2 模型，按固定最大 token 数、固定 CLS pooling、固定向量维度和 L2 归一化生成向量。保存论文 ID、输入字段、输入哈希、模型版本、向量维度、向量键、向量文件与生成状态，并执行输入哈希、模型哈希、维度、有限数值和归一化范数的机械验收。


* **受控关键词与研究领域**：单篇标注任务读取论文 ID、标题、可用摘要、完整的受控关键词词表和固定 prompt，输出包含 `paper_id`、`input_sha256`、`keyword_ids` 及 `evidence`（标明 `keyword_id`、`field` 为 `title` 或 `abstract`、连续原文引文 `quote`）的结构化结果。每个关键词必须至少有一条来自标题或摘要的连续原文证据；空关键词列表是有效结果，与任务未执行分别保存。旧关键词标注只有在相同论文 ID、同一版本的受控关键词词表、标题与摘要完整一致（或仅存在 NFKC、大小写、空白等格式差异）、所有旧引文均能在当前文本中重新定位且结构通过机械校验时才作为派生结果复用；文本变化、新论文或旧引文失效均进入固定模型任务。研究领域由版本化的受控关键词映射规则派生生成。


* **人员归一**：将逐篇作者 occurrence、数据库作者身份和实验室人员实体分开处理，依据相同 OpenAlex author ID、相同且格式有效的 ORCID、规范化姓名、共同作者结构、共同机构、署名顺序、用户明确人员名单及已知同名约束建立归并证据链。固定执行硬性分离约束：东南大学 Bo Han 与香港浸会大学或 RIKEN 的同名作者分开；东南大学 Xiaoyu Wang 与 Monash University 的同名作者分开；Junfeng Fang 与 Jingwei Fang 分开；Hao Chen 的不同论文记录在缺少额外证据时保持独立；同名作者不能仅凭姓名或单位合并。缺少 OpenAlex ID、ORCID 和足够合著锚点，或存在未决同名冲突的记录进入阻塞核对队列（`ambiguous`）；已有稳定 ID 或 ORCID 但同名家族仍存其他数据库组件或分类待补证据的记录标为非阻塞警告（`warning`）。


* **作者画像聚合**：按署名位置计算论文贡献权重——第一作者为 `1.0`，其他作者为 `0.2`；导师一作、学生二作时，学生按一作（`1.0`）计入；同一人员在同一篇论文中重复出现只计一次贡献；未确认的多个临时人员键不自动合并。计算作者在某关键词上的分数时，只使用已完成关键词标注的论文，对关键词权重求和后除以该作者已完成关键词论文的权重总和（已确认为空的关键词标注计入分母，尚未完成的关键词任务不计入分母）。存在人员身份阻塞项或未完成关键词任务时，画像标记为 `partial` 并记录具体依赖项。



**输出**

* 研究领域标签、带连续原文证据的 版本化的受控论文关键词、本地 SPECTER2 语义向量。


* 人员归一映射结果（occurrence ID、临时或已确认人员键、归一来源、证据链、人员分类与状态）及阻塞/警告队列。


* 作者画像（人员键、显示姓名、分类、身份状态、参与论文及权重、有效关键词论文数、关键词分数、完整或部分状态及依赖项）与语义关联依据。



**可能产生的状态**

已确认（`ready`）、明确为空（`empty`）、待生成（`not_generated`）、非阻塞警告（`warning`）、多候选歧义（`ambiguous`）、结果部分取得（`partial`）、内容无效（`invalid`）。

**阶段悬浮说明**

> 这一阶段从锁定的论文文本和逐篇署名生成派生特征与作者画像。SPECTER2 向量、版本化的受控关键词、人员实体归并和署名加权画像均保存完整的输入哈希、证据链和配置指纹，支持独立重算，且不修改底层论文事实字段。
> 
> 

## 五、图中每个数据节点的文字

以下是图表中 26 个数据节点的正式名称、所在行位置、对应 DOM `data-flow-node` 标识和悬浮说明。节点标签与页面画布完全一致；悬浮框说明输入来源、采用规则和交接用途。

### 基本信息行（`data-flow-group="basic"`）

#### 1. 标题（主页未定稿，`home-title`）

* **节点标签**：**标题**

* **悬浮说明**：从实验室主页论文段落直接提取的原始标题文本。Unicode NFKC、大小写、标点、连字符和空白规范化仅用于识别主页内重复展示和构造检索词，原始标题字符串原样保留。



#### 2. 署名（主页未定稿，`home-authors`）

* **节点标签**：**署名**

* **悬浮说明**：主页条目记载的原始作者姓名字符串与署名顺序。它用于与 OpenAlex 候选比对作者交集，当数据库缺少作者名单时不会被空值覆盖。



#### 3. 发表情况（主页未定稿，`home-publication`）

* **节点标签**：**发表情况**

* **悬浮说明**：主页记载的年份、会议简称或期刊名称、预印本状态及 DOI/arXiv 链接。载体名称经规范化后用于候选比对，主页原始描述持续保留。



#### 4. 论文标题（核对后定稿，`lab-title`）

* **节点标签**：**论文标题**

* **悬浮说明**：通过身份核对后正式采用的论文标题。排版与固定拼写差异可归一，涉及研究任务、方法或对象的实质性词义变化需额外证据；未确认身份的条目继续保留主页标题。



#### 5. 作者名字（核对后定稿，`lab-authors`）

* **节点标签**：**作者名字**

* **悬浮说明**：身份确认后提取的逐篇作者署名（occurrence），包含作者顺序、规范化姓名、OpenAlex author ID、ORCID、机构和名单候选。逐篇署名与实验室人员实体分开保存。



#### 6. 论文录用情况（核对后定稿，`lab-publication`）

* **节点标签**：**论文录用情况**

* **悬浮说明**：核对确认后的发表年份、规范化会议或期刊载体、论文类型与版本状态。主页原始发表描述与 OpenAlex 采用值同时保留。



#### 7. 确认标识与版本（核对后定稿，`identity`）

* **节点标签**：**确认标识与版本**

* **悬浮说明**：唯一锁定的 OpenAlex work ID、DOI、正式版或预印本状态及版本判断依据。同作品多版本在满足标题家族、作者顺序与载体兼容时优先采用正式版，作为精确详情查询的唯一入口。



### 内容与主题行（`data-flow-group="content"`）

#### 8. 摘要（`lab-abstract`）

* **节点标签**：**摘要**

* **悬浮说明**：阶段三按确认 work ID 重新精确查询取得的论文摘要。需通过固定规则过滤会议元信息、网页提示语、错误页面和重复字段；无效摘要标为 `invalid` 并保留原始响应，不进入特征计算。



#### 9. 数据库关键词（`lab-keywords`）

* **节点标签**：**数据库关键词**

* **悬浮说明**：精确详情查询返回的 OpenAlex 原生 `keywords` 字段及分数。保留数据库原始来源值，与阶段五基于 版本化的受控关键词词表生成的“论文关键词”分开管理。



#### 10. 数据库主题（`lab-topics`）

* **节点标签**：**数据库主题**

* **悬浮说明**：精确详情查询返回的 OpenAlex 原生 `topics` 学科主题分类。作为数据库事实字段保存，用于展示与对照，不直接替代受控关键词或派生研究领域。



### 引用与统计行（`data-flow-group="citations"`）

#### 11. 被引数（`lab-counts`）

* **节点标签**：**被引数**

* **悬浮说明**：同时保存 OpenAlex 主记录的 `cited_by_count`、被引查询接口报告的总数、年度被引数（`counts_by_year`）、查询时间与完整性状态。优先采用被引查询接口报告总数，不用被引名单长度替代被引数。



#### 12. 引用文献（待补全名单，`reference-list`）

* **节点标签**：**引用文献**

* **悬浮说明**：精确详情中 `referenced_works` 返回的该论文主动引用的作品 ID 列表。分别记录正常取得、明确空列表、查询失败或身份未确定状态，交由阶段四补全详情。



#### 13. 被引记录（待补全名单，`citing-list`）

* **节点标签**：**被引记录**

* **悬浮说明**：通过被引查询接口获取的引用该论文的作品 ID 列表。独立保存查询路径、接口报告总数、已取得名单与分页截断状态（`partial`）。



#### 14. 外部文献信息（`external-info`）

* **节点标签**：**外部文献信息**

* **悬浮说明**：一层引用与被引邻域中所有唯一外部作品的详情记录及网络入选集合。完整外部记录全部保留；进入网络的节点必须与至少两篇不同实验室论文存在直接引用或被引关系。



#### 15. 引用文献（补全后）（`reference-list-resolved`）

* **节点标签**：**引用文献（补全后）**

* **悬浮说明**：主动引用文献列表经过批量查询、遗漏单查和 canonical ID 重定向合并后的完整记录集合。查不到详情的 ID 仍保留请求状态与失败原因。



#### 16. 被引记录（补全后）（`citing-list-resolved`）

* **节点标签**：**被引记录（补全后）**

* **悬浮说明**：施引文献列表经过 canonical ID 去重和详情补查后的完整记录集合。完整关系名单与前端网络节点筛选结果分开保存。



### 文献特征行（`data-flow-group="paperfeatures"`）

#### 17. 供文献特征使用的论文标题（`feature-title`）

* **节点标签**：**论文标题**

* **悬浮说明**：传入阶段五特征生成任务的已核对论文标题文本。与可用摘要一同计算 SHA-256 输入指纹，作为 SPECTER2 向量与受控关键词标注的锁定文本输入。



#### 18. 供文献特征使用的摘要（`feature-abstract`）

* **节点标签**：**摘要**

* **悬浮说明**：传入阶段五特征生成任务的通过质量检查的本篇摘要。当摘要缺失或被判为无效时，特征生成任务自动仅使用论文标题执行，并如实记录输入状态。



#### 19. 研究领域（`directions`）

* **节点标签**：**研究领域**

* **悬浮说明**：由受控关键词和版本化映射规则派生生成的粗粒度研究领域标签，用于图谱节点染色与检索筛选，不修改底层数据库主题事实。



#### 20. 论文关键词（`controlled-keywords`）

* **节点标签**：**论文关键词**

* **悬浮说明**：基于版本化的受控关键词词表生成的论文关键词列表。每个关键词均附带标题或摘要中的连续原文引文并通过机械校验；未命中词表时，空列表属于有效确认结果（`empty`）。



#### 21. 语义向量（`vector`）

* **节点标签**：**语义向量**

* **悬浮说明**：由固定版本的本地 SPECTER2 模型对标题和合格摘要生成的定长 L2 归一化向量。完整保存输入哈希、模型版本、CLS 池化方式、维度与范数验收状态。



### 作者画像行（`data-flow-group="profiles"`）

#### 22. 供作者画像使用的作者名字（`profile-authors`）

* **节点标签**：**作者名字**

* **悬浮说明**：进入人员归一与画像聚合的逐篇作者 occurrence 输入。结合 OpenAlex ID、ORCID、合著结构与分离约束完成人员实体映射，并根据署名顺序确定单篇贡献权重。



#### 23. 供作者画像使用的论文关键词（`profile-keywords`）

* **节点标签**：**论文关键词**

* **悬浮说明**：已完成机械校验的论文受控关键词结果，作为计算作者关键词得分的分子输入；已确认为空的关键词标注计入作者画像归一化分母。



#### 24. 供作者画像使用的语义向量（`profile-vectors`）

* **节点标签**：**语义向量**

* **悬浮说明**：已验收通过的论文级 SPECTER2 语义向量，为计算作者之间的主题与语义关联提供底层表征输入。



#### 25. 关键词画像（`keyword-profile`）

* **节点标签**：**关键词画像**

* **悬浮说明**：按第一作者 1.0、其他作者 0.2（导师一作、学生二作时学生按 1.0 计入）聚合归一化得到的作者受控关键词分布。存在人员阻塞项或未完成关键词任务时标为 `partial`。



#### 26. 语义关联依据（`semantic-evidence`）

* **节点标签**：**语义关联依据**

* **悬浮说明**：由论文语义向量、受控关键词分布与已确认的人员归属共同派生的论文间语义关联及作者间主题关联依据。未确认归并的同名作者保持独立，不自动合并关联。



## 六、图中处理动作的文字

以下 5 个处理动作节点对应画布中的 `.flow-process` 按钮（外加阶段一隐含的本地解析动作），悬浮说明同时回答“输入什么、怎样处理、输出什么”。

### 0. 解析主页清单（阶段一表头动作，`data-stage="import"`）

* **动作标签**：**整理实验室清单（本地解析）**

* **悬浮说明**：从实验室主页原始 HTML 快照中解析论文段落，提取原始标题、署名、年份、发表情况和链接；对标题做排版规范化以识别主页内重复展示，保存每次展示的 occurrence 并输出去重后的唯一论文记录。



### 1. 检索与规则核对（`data-flow-node="locate"`）

* **动作标签**：**检索与规则核对**

* **悬浮说明**：以主页 DOI、arXiv 标识、标题限定搜索、完整标题搜索和有限标题变体建立 OpenAlex 候选；仅使用纯身份字段联合检验标题词汇、作者交集、年份、规范化载体、非论文类型排除与正式版优先条件，输出采用的论文标题、作者名字、录用情况及确认的 work ID 与版本。



### 2. 按标识采集文献详情（`data-flow-node="collect"`）

* **动作标签**：**按标识采集文献详情**

* **悬浮说明**：按阶段二确认的 OpenAlex work ID 重新发起精确查询与被引分页查询；检验摘要自然语言有效性，分别保存主记录被引数、查询接口总数与双向引用名单，并执行身份漂移检查，输出合格摘要、数据库关键词、数据库主题、被引数、引用文献和被引记录。



### 3. 采集外部文献并补全记录（`data-flow-node="external"`）

* **动作标签**：**采集外部文献并补全记录**

* **悬浮说明**：汇集实验室论文主动引用的作品与引用实验室论文的作品，剔除实验室自身论文后，按先批量、后逐个补漏的方式查询一层唯一外部 ID；处理 canonical ID 重定向合并，筛选连接至少两篇不同实验室论文的网络节点，输出外部文献信息与补全后的引用、被引记录。



### 4. 生成文献特征（`data-flow-node="features"`）

* **动作标签**：**生成文献特征**

* **悬浮说明**：读取已核对的论文标题和合格摘要（无摘要时仅用标题），通过固定版本的本地 SPECTER2 生成 L2 归一化语义向量；基于版本化的受控关键词词表抽取带连续原文证据的论文关键词（或复用符合严苛一致性条件的旧标注），并按版本化规则映射研究领域。



### 5. 聚合作者画像（`data-flow-node="profile"`）

* **动作标签**：**聚合作者画像**

* **悬浮说明**：依据 OpenAlex author ID、有效 ORCID、合著结构、机构、署名顺序和硬性同名分离约束将逐篇作者署名归一到实验室人员实体；按一作 1.0、其他 0.2（导师一作学生二作时学生按 1.0）加权归一化已完成标注论文的关键词与语义特征，输出关键词画像与语义关联依据。



## 七、连线悬浮说明

连线说明对应 SVG 中的 `data-flow-edge`，只解释数据如何交接与过滤，不重复节点定义。

* **标题 / 署名 / 发表情况 → 检索与规则核对（`flow-edge-0, 2, 4`）**：主页提取的三项原始文本与内含的 DOI/arXiv 标识共同作为身份检索线索；主页原文持续保留，检索过程使用排版规范化副本。


* **检索与规则核对 → 论文标题 / 作者名字 / 论文录用情况（`flow-edge-1, 3, 5`）**：候选通过联合规则检验后，分别输出采用的标题、逐篇作者署名列表和录用情况；各字段独立记录状态，数据库缺失作者时不会覆盖主页原始署名。


* **检索与规则核对 → 确认标识与版本（`flow-edge-6`）**：只有唯一确认或满足正式版优先条件的候选才会生成确认的 OpenAlex work ID；未匹配或多候选歧义条目在此收束并阻断后续详情查询。


* **确认标识与版本 → 按标识采集文献详情（`flow-edge-7`）**：精确详情查询只接收已确认的 OpenAlex work ID 作为入口；身份搜索阶段附带的摘要、计数和引用字段不直接跨阶段沿用。


* **按标识采集文献详情 → 摘要 / 数据库关键词 / 数据库主题 / 被引数（`flow-edge-8, 9, 10, 11`）**：由确认 work ID 的精确详情接口返回，各自独立保存来源、质量检查结果与字段状态。


* **按标识采集文献详情 → 引用文献 / 被引记录（`flow-edge-12, 15`）**：精确查询分别输出主动引用的作品 ID 清单与分页拉取的施引作品 ID 清单，两者使用不同路径保存并各自记录分页完整性。


* **引用文献 / 被引记录 → 采集外部文献并补全记录（`flow-edge-13, 16`）**：两份名单去除实验室自身论文后，合并提取出一层邻域的唯一外部 ID 集合，带着原始关系方向进入批量与单篇补查。


* **采集外部文献并补全记录 → 外部文献信息 / 引用文献（补全后） / 被引记录（补全后）（`flow-edge-18, 14, 17`）**：经 canonical ID 重定向合并后，并列输出完整的一层外部文献库、筛选出的双连接网络节点集合以及补全详情后的双向引用记录。


* **论文标题 / 摘要 → 生成文献特征（`flow-edge-24, 25`）**：实验室论文与入选网络外部论文的锁定标题和合格摘要（附 SHA-256 输入指纹）进入特征流水线；无效或缺失摘要被拦截，任务降级为仅使用标题。


* **生成文献特征 → 研究领域 / 论文关键词 / 语义向量（`flow-edge-19, 20, 21`）**：在固定模型权重、版本化的受控关键词词表和原文证据机械校验下，分别输出三项派生文献特征。


* **作者名字 / 论文关键词 / 语义向量 → 聚合作者画像（`flow-edge-26, 27, 28`）**：逐篇作者名字提供人员归一锚点与署名顺序权重，已完成校验的论文关键词与语义向量提供聚合内容；单篇论文重复署名只计一次，未完成关键词标注的论文不计入分母。


* **聚合作者画像 → 关键词画像 / 语义关联依据（`flow-edge-22, 23`）**：在人员归并证据链与依赖检查通过后，输出每位实验室人员的加权关键词画像与主题关联依据；存在阻塞身份或未完成标注时标记为 `partial`。



## 八、图下详细解释段落（对应 `#workflow-explanations`）

这些段落放在流程图下方（`#inspector` 区域），严格对应现有的 9 个 `<article id="explain-*">` 章节结构，用完整段落解释数据扩大、收束、固定与验收的机制，不重复罗列图上的节点名称。

### 1. 页面说明（`#explain-purpose`）

Lab Atlas 将实验室主页上的论文展示记录逐步整理为来源清晰、证据完整、可追溯的论文、作者和引用特征。信息在各阶段沿着明确的交接边界受控流转：主页整理阶段完整保留页面原始展示记录并去重建立内部论文 ID；身份核对阶段在多路径检索候选中收束出唯一的数据库作品标识；详情采集阶段针对确认标识精确获取论文自身内容与双向引用清单；外部文献阶段向外扩展一层引用邻域并筛选核心网络节点；特征与画像阶段在固定文本输入和人员证据链之上生成语义向量、受控关键词和作者画像。

系统中的每一个字段、关系端点和派生结果都保存数据来源、查询路径、采用依据和明确状态。基础事实字段与派生计算特征分开管理，互不覆盖；主页单次展示（occurrence）、去重后的论文身份、逐篇作者署名、实验室人员实体和作者研究画像也分别作为独立对象处理，各自遵循严格的确认与交接规则。自动程序负责全部规范化、匹配、校验与派生计算；无法由已有证据唯一确定的记录保持明确的不确定状态并进入结构化核对队列。

### 2. 事实来源与依赖边界（`#explain-sources`）

全流程的基础事实仅来自三个标准来源：实验室主页原始 HTML 快照、用户确认的实验室人员名单和 OpenAlex 数据库。主页原始标题、原始作者字符串、原始年份与发表情况、外部链接以及所在栏目和顺序在全流程中持续保留，不因接入外部数据库而被覆盖；用户提供的实验室人员名单与同名约束用于确立人员实体边界；OpenAlex 用于论文身份核对、精确文献详情采集、作者标识获取和双向引用关系构建。

Semantic Scholar、Crossref、Google Scholar、DBLP 和独立论文发布页不属于当前标准采集流程的数据来源。保存在 `_legacy/` 中的旧版多源数据只用于字段到位率、网络规模和数值变化的结果对照，不能用来回填或补充新流程的论文事实、作者身份或引用关系。旧关键词标注只有在同时满足相同论文 ID、同一版本的受控关键词词表、标题与摘要文本完整一致（或仅存在 NFKC、大小写、空白等纯格式差异）、所有旧引文均能在当前文本中精确定位且结构通过机械校验时，才能作为派生结果复用。

### 3. 从主页条目到唯一作品（`#explain-identity`）

主页上的论文标题、署名、发表情况和内含链接共同构成论文身份的初始线索。在整理主页清单并完成标题排版去重后，系统按固定优先级依次执行主页 DOI 查询、主页 arXiv 标识查询、OpenAlex `search.title` 完整标题查询、`search` 完整标题查询以及有限标题变体查询（含固定拼写修正、连字符与空格变体、冒号前后片段、较长标题的前后半段），完整保存每条查询的请求地址、HTTP 状态、响应指纹与候选筛选结果。身份检索阶段只保留 ID、标题、DOI、论文类型、年份、作者列表和发表位置等纯身份字段，并将数据集、项目页面、资助记录、参考文献条目等非论文对象直接排除。

候选是否合格由标题、作者、年份、发表载体和版本关系联合决定：排版、大小写、标点、连字字符和固定拼写差异可以自动归一，但增加、删除或替换研究任务、方法或对象词汇的实质性标题变化需要额外证据；作者通常需满足固定交集数量或比例，或由主页 DOI/arXiv 直接指向（当 OpenAlex 缺少作者名单时，需满足标题、年份、发表载体和正式版本条件全部严格吻合，且数据库空值不覆盖主页作者名单）；同一作品并存预印本与正式版时，需先确认属于同一标题家族、作者顺序完整兼容、年份与载体符合版本演进关系且属于可接受的正式论文类型，再优先采用正式版（同标题但作者顺序不兼容的候选不自动合并）。确认身份后，OpenAlex work ID 成为详情查询的唯一入口；未匹配或多候选歧义的记录保留主页原始字段与全部查询证据，后续阶段不会用模糊相似度替代唯一身份。

### 4. 论文详情与引用关系（`#explain-details`）

论文身份确认后，系统仅针对锁定的 OpenAlex work ID 重新执行精确详情查询，身份搜索阶段附带的摘要、计数、主题和关键词字段不直接进入采用结果。摘要、OpenAlex 原生关键词、OpenAlex 研究主题、被引统计、引用文献和被引记录均从精确详情阶段取得。其中，摘要必须通过固定质量规则检查，过滤会议元信息、网页提示语、访问错误页面或重复字段，无效摘要保留原始响应与原因但绝不进入语义向量或关键词任务；被引次数同时保存 OpenAlex 主记录 `cited_by_count`、被引查询接口报告总数、查询时间与完整性状态，优先采用被引查询报告总数并保留主记录计数作对照，不用被引名单长度替代被引次数。

引用文献表示该论文主动引用的作品，被引记录表示引用该论文的作品。两份名单使用不同的字段与查询路径分别保存，各自独立记录明确为空、查询失败、分页截断（`partial`）和身份未确定状态。精确详情查询同时会再次核对返回记录的 OpenAlex ID、规范化标题、DOI、有序作者、年份、发表载体和正式版状态；一旦发现身份签名相较于阶段二发生漂移，阶段二身份保持不变，阶段三详情不覆盖阶段二身份，并将变化记录交回身份核对队列重新审查。

### 5. 一层外部邻域（`#explain-external`）

外部文献来自已确认实验室论文的引用文献名单和被引记录名单。系统去除实验室论文自身后，对所有唯一外部 OpenAlex ID 执行“先批量查询、批量遗漏 ID 再逐个精确补查”的策略，完整记录 HTTP 404、查询失败和 OpenAlex canonical redirect，使用 canonical ID 合并重复记录（若某条外部记录后来被识别为实验室论文，则重新划入实验室集合），并保存每条外部文献的详情、关联实验室论文及关系方向。查询范围严格停留在一层外部邻域，外部文献继续引用的作品不再递归展开，外部文献之间也不建立引用关系边。

完整外部文献记录与进入图谱的网络节点集合分开保存。网络候选节点要求与至少两篇不同实验室论文存在直接引用或被引关系：连接数在语义边、页面筛选和其他 UI 规则之前，直接依据完整的引用与被引名单并按 canonical OpenAlex ID 去重计算，同一对论文的重复关系只算一次，相反方向的关系对同一邻居只算一个，不叠加年份或被引次数门槛，也不用单连接文献补满预算（存在预算上限时，按连接到不同实验室论文的数量排序，再以 OpenAlex ID 作为稳定的并列排序键）。

### 6. 固定输入生成派生特征（`#explain-features`）

阶段五对实验室论文和符合网络筛选条件的外部论文生成派生特征，所有特征均基于锁定的论文标题和通过质量检查的摘要计算，不修改底层论文事实字段。当论文没有可用摘要时，系统仍可使用标题生成特征，绝不生成虚构摘要，且标题与摘要的精确输入 SHA-256 指纹必须先行保存。语义向量由固定权重和固定版本的本地 SPECTER2 模型生成：将标题与摘要拼接，采用固定最大 token 数、固定 CLS pooling 池化方式、固定向量维度并执行 L2 归一化，同时保存模型版本、输入哈希、向量键与生成状态，验收检查确保输入哈希与模型哈希一致、维度正确、数值为有限值且范数符合归一化要求。

受控关键词使用版本化的受控关键词词表，标注任务每次仅读取单篇论文的标题、可用摘要、完整的受控关键词词表和固定 prompt。每个输出的关键词都必须附带至少一条来自标题或摘要的连续原文引文证据（明确标出字段来源与精确原文片段）；当文本未命中任何词表概念时，空关键词列表是有效结果，系统将空标注结果与任务未执行状态分别保存。旧标注只有在输入文本与词表完全一致且全部旧引文可在当前文本中精确定位时才予复用；文本内容变化、新论文、旧标注未通过结构检查或引文失效时，均重新进入固定模型标注任务。研究领域标签则由受控关键词经版本化映射规则派生生成。

### 7. 逐篇署名与实验室人员（`#explain-people`）

系统将单篇论文中的逐篇作者署名（occurrence）、OpenAlex author 身份和实验室人员实体分开保存。阶段二的姓名规范化只处理大小写、标点、`Lastname, Firstname` 形式、OpenAlex 导出的 `id_orcid` 尾部和明确排版差异，姓名相同不能单独触发跨论文人员合并。进入阶段五的人员归一后，自动规则综合使用相同 OpenAlex author ID、相同且格式有效的 ORCID、规范化姓名、共同作者结构、共同机构、署名顺序、用户明确人员名单以及论文归属证据建立归并证据链，并严格执行固定写入规则的分离约束：东南大学 Bo Han 与香港浸会大学或 RIKEN 的同名作者分开；东南大学 Xiaoyu Wang 与 Monash University 的同名作者分开；Junfeng Fang 与 Jingwei Fang 分开；Hao Chen 的不同论文记录在缺少额外证据时保持独立。

经过自动归一，具备稳定 OpenAlex ID 或 ORCID 但同名家族仍存在其他数据库组件或分类证据尚不完整的记录标为非阻塞警告（`warning`），它们可以独立参与临时画像，但不会自动产生跨组件合并；没有 OpenAlex ID、没有 ORCID、缺少足够共同作者锚点或已知同名无法区分的记录进入阻塞核对队列（`ambiguous`），不自动参与最终人员去重。作者画像在人员对应、论文受控关键词和署名顺序之上按贡献权重聚合：第一作者权重为 `1.0`，其他作者权重为 `0.2`，导师一作、学生二作时学生按一作（`1.0`）计入，同一人员在同一篇论文中重复出现只计一次贡献，未确认的多个临时人员键不自动合并。关键词分数只使用已完成关键词标注的论文加权求和，并以该作者已完成关键词论文的权重总和进行归一化（已确认为空的关键词标注计入分母，尚未完成的关键词任务不计入分母）；存在人员身份阻塞项或关键词任务未完成时，画像标记为 `partial` 并记录产生部分状态的依赖项。

### 8. AI 介入的边界与困难（`#explain-ai-boundaries`）

在全流程中，主页解析、标题规范化、去重、OpenAlex 查询、候选评分、版本选择、质量检查、引用整理、外部文献补全与筛选、SPECTER2 向量生成、关键词证据机械校验、人员 ID 组件归并、作者画像计算、指纹校验与快照重放均由纯规则自动完成。AI 仅在以下三个可选或受控环节介入，且所有 AI 输出始终先成为结构化候选，必须经过输入指纹校验、prompt 与词表校验、输出字段校验、原文证据校验、用户约束校验、确定性规则重新执行及下游重算后才能进入采用结果：

* **论文身份核对**：面对标题近似但无唯一记录、预印本与正式版并存、发表年份不一致、数据库缺失作者列表或同一作品存在多个候选版本等困难，AI 仅读取已保存的主页记录、OpenAlex 候选、查询路径及标题/作者/年份/载体指标，输出包含 `paper_id`、`verdict`（`agree | needs_rule_revision | insufficient_evidence`）、`candidate_id`、`evidence_paths` 和 `reason` 的结构化审查意见。AI 不能查询外部网站、不能创建新的 OpenAlex ID、不能用语义相似标题替代身份标识，也不能直接修改采用结果或将审查意见直接写入论文事实。


* **人员归一**：面对中英文同名作者、同一姓名对应多个 OpenAlex author ID、ORCID 冲突、学者跨机构变动、数据库缺少作者 ID 以及实验室名单与数据库作者无法直接字面对应等困难，AI 读取逐篇署名、OpenAlex author ID、ORCID、机构、共同作者、实验室人员名单与已知同名约束，输出包含 `input_sha256` 和 `suggestions`（含 `occurrence_ids`、`verdict` 为 `propose_same_person | keep_separate | insufficient_evidence`、`evidence_paths`、`reason`）的建议。AI 不能仅凭姓名或单位相同合并、不能自创映射、不能覆盖用户分离约束，也不能直接改变作者分类或最终人员键；只有将带证据的记录写入 `person-mappings.json` 并重新执行人员阶段确定性规则，才会改变采用的人员对应。


* **关键词标注**：面对任务词、方法词与应用对象同时出现、标题明确但摘要缺失、研究背景与论文贡献容易混淆以及受控词表内父子概念层级并存等困难，AI 只读取单篇论文标题、合格摘要和版本化的受控关键词词表，输出包含 `paper_id`、`input_sha256`、`keyword_ids` 和连续原文引文 `evidence` 的结果。AI 不能根据常识补充文本未出现的任务、不能把背景工作或引用文献内容当成当前论文贡献、不能自创词表外关键词或捏造引文，也不能因下位子词出现而自动推断上位父词已出现。



### 9. 状态与异常处理（`#explain-states`）

每个字段、关系端点与派生特征都使用以下十种明确状态之一记录当前质量与进展：`ready`（成功取得有效非空值或唯一确认身份）、`empty`（查询或标注成功，返回明确空列表）、`missing`（记录存在，但数据源未提供该字段值）、`query_failed`（请求失败或未取得有效响应）、`identity_unresolved`（论文身份未确定，因此阻断后续详情查询）、`partial`（查询结果被截断、分页未完成或画像依赖只有部分就绪）、`ambiguous`（存在多个合格候选或同名冲突，无法唯一采用）、`invalid`（返回了内容，但经固定质量或证据规则检验被判定为无效）、`not_generated`（派生任务的输入已经准备，但生成任务尚未完成）和 `warning`（当前记录已有稳定身份依据，但在同名家族、单位变体或名单分类上存在附加疑点）。

异常处理遵循严格的保留与隔离原则：`warning` 不会覆盖已有的 `ready` 身份字段，而 `ambiguous` 会阻塞最终人员归一与画像确认。当 OpenAlex 找不到论文时，系统保存所有查询路径、HTTP 状态、查询字符串、最接近候选的标题相似度、作者交集、年份差异和拒绝原因，主页论文继续保留在清单中，详情维持 `identity_unresolved`；当合格候选过多无法唯一区分时，保存全部合格候选及其版本、载体比对指标并进入多重匹配队列（`ambiguous`）；当模型输出不合格时，保存原始请求、原始响应、模型版本、prompt 指纹、输入指纹、机械校验错误和重试次数，直至结果修复并重新通过输入、词表、连续引文和响应指纹校验后才进入采用结果。

### 10. 验收与可重放性（`#explain-acceptance`）

快照冻结前执行全量机械验收，逐项核查：每篇主页论文都有明确身份决策；每个查询候选都来自本轮保存的响应；OpenAlex 请求路径符合允许范围；没有把身份搜索附带字段直接当作采用详情；每个关系端点都有明确状态；外部文献只扩展一层邻域；所有网络节点均满足至少连接两篇不同实验室论文；阶段输入指纹与输出指纹一致；SPECTER2 向量维度、有限数值、L2 范数和模型版本正确；每个受控关键词引文均连续存在于当前标题或摘要文本中；全部人员 occurrence 均有明确归宿且硬性同名分离约束未被覆盖；受控关键词、人员归一和作者画像均支持从固定输入独立重算。

每次运行完整保存规范协议、采集代码、派生代码、固定 prompt、版本化的受控关键词词表、主页 HTML 快照、用户人员名单、OpenAlex 原始响应、模型配置、模型响应及所有输入输出哈希；若运行过程中代码或输入发生改变，冻结操作立即拒绝继续。冻结结果必须在断开网络请求的情况下通过离线重放校验：重新读取本轮输入与保存的原始响应，重新执行确定性规则并生成各阶段输出，比对文件指纹，一旦发现差异即停止冻结。发布时依次完成采集与派生、机械验收、未决队列保存、旧版结果对照、独立候选快照创建与指纹校验、上一版快照归档与底层快照替换；数据快照发布与前端网络、检索页面的切换作为两个独立动作分开执行。

## 九、状态定义速查表（供悬浮框与文档查阅）

状态是字段、关系端点或派生结果的核心属性。页面只解释状态含义和后续处理方式，不显示当前统计数量。

| 状态 | 定义 | 后续处理 |
| --- | --- | --- |
| 已确认 / `ready` | 成功取得符合固定质量规则的有效非空值，或已由完整证据链唯一确认身份。

 | 正常交接给依赖它的下一阶段计算与展示。

 |
| 明确为空 / `empty` | 查询或受控标注正常完成，返回明确的空列表（如暂无被引记录或文本未命中受控词表）。

 | 作为有效事实保留；在作者画像计算中，已确认的空关键词标注正常计入归一化分母。

 |
| 字段缺失 / `missing` | 论文或作者记录本身存在，但数据源没有提供该目标字段值（如数据库无摘要或无 ORCID）。

 | 保留响应与缺失状态，不生成虚构值；摘要缺失时向量与关键词任务仅使用标题执行。

 |
| 查询失败 / `query_failed` | 接口请求发生错误、返回 HTTP 404/5xx 或未能取得有效响应报文。

 | 保存请求地址、参数、HTTP 状态码与失败原因供后续补查，不以空列表替代。

 |
| 身份未确定 / `identity_unresolved` | 主页论文在 OpenAlex 中未找到合格候选，或现有证据不足以确立唯一 work ID。

 | 保留主页原始展示记录与全部查询路径，暂停依赖该身份的阶段三精确详情查询与引用扩展。

 |
| 结果部分取得 / `partial` | 引用或被引查询结果被截断、分页未完成，或作者画像所依赖的人员身份/论文关键词尚未全部完成。

 | 保存已取得部分与缺口依赖项；作者画像标为 `partial`，未完成的关键词任务不计入分母。

 |
| 多候选歧义 / `ambiguous` | 存在多个合格的论文身份候选，或人员归一中存在同名冲突、缺少身份锚点，无法唯一采用。

 | 保留全部候选指标并进入阻塞核对队列（blocking review queue），阻塞最终人员合并或画像确认。

 |
| 内容无效 / `invalid` | 接口或模型返回了非空内容，但经固定质量规则检验被判定为无效（如摘要为会议通知/报错页，或模型引文不在原文中）。

 | 保留原始响应与违规原因供审计，拦截该内容使其不进入语义向量或关键词采用结果。

 |
| 待生成 / `not_generated` | 派生任务的输入文本与配置已经准备就绪，但向量生成或关键词标注任务尚未完成。

 | 维持待生成标记，不计入作者画像的有效论文分母，待任务执行并校验通过后更新。

 |
| 非阻塞警告 / `warning` | 当前记录已有稳定身份依据（如明确的 OpenAlex ID 或 ORCID），但在同名作者家族、单位变体或名单分类上存在附加疑点。

 | 不覆盖已有的 `ready` 身份字段，允许其独立参与临时画像，但在补充证据前不触发跨组件自动合并。

 |

## 十、写作与界面实现要求（维护准则）

1. **层级清晰**：阶段表头使用简短主副标题；悬浮说明控制在 1~2 段内，只解释该节点、动作或连线的输入、处理逻辑、输出与状态，不加入当前运行统计。


2. **术语先行**：首次出现的专有概念（如 `occurrence`、`canonical ID`、受控关键词、一层邻域）先给平实定义，再交代技术规则。


3. **正面陈述**：直接陈述“规则采用哪些证据”“字段在何时锁定”“异常进入何种状态”，不使用“这不是……而是……”“并不是因为……”“不能简单理解为……”“不能据此断定……”等防御性句式，也不使用“候选关联”“确定后使用”等含糊措辞。
4. **长期有效**：不写当前运行进度，不写当前论文数、作者数、关键词完成数、成功率、失败率或队列条数，不写“当前已完成”“尚未完成”“本轮结果”“最新快照”“页面尚未切换”等阶段性汇报措辞。


5. **严守事实边界**：基础事实只写实验室主页、用户确认的实验室人员名单和 OpenAlex；右上角 `#info` 弹窗与正文保持一致，彻底移除将 Semantic Scholar 或原始发布页作为补充来源的旧表述；AI 始终表述为受控候选审查或固定抽取工具，不写成事实来源或直接采用结果。


6. **视觉与布局一致**：保持画布从左向右的箭头流向；不在图表下方的详细段落中机械罗列图中已经出现的节点名称，图下段落专注于解释数据扩缩机制、证据门槛与可重放验收规则。
